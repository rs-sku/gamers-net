# Social net for computer games enjoyers

## Пагинация API

GET-списки пользователей (`/api/v1/users`), игр (`/api/v1/games/all`),
игр пользователя (`/api/v1/games?user_id=...`), друзей и входящих/исходящих
заявок принимают `limit` (по умолчанию 50, от 1 до 100) и `offset`
(по умолчанию 0, неотрицательный).

Например: `/api/v1/users?limit=100&offset=100`.
Формат ответа сохранён: массив записей; для друзей — `{ "friends": [...] }`.
Следующая страница получается увеличением `offset` на `limit`;
страница короче `limit` означает конец списка.
PostgreSQL-списки упорядочены по ID, друзья — по имени.
Offset-пагинация не фиксирует снимок данных: изменения между запросами
могут сдвигать границы страниц.

Текущий фронтенд собирает страницы целиком, чтобы сохранить поиск игроков,
ссылки на профили и статусы заявок. Для больших объёмов следующий шаг —
постраничный интерфейс и поиск на сервере.

Проверки без подключения к рабочим базам данных:

```bash
.venv/bin/python -m unittest discover -s tests -v
node --experimental-default-type=module --test tests/test_pagination.mjs
.venv/bin/ruff check backend tests
```
